## 1. 프로젝트 개요

"인사카드"는 100명 이하 회사에서 지원자, 재직자, 퇴사자의 이력을 한 사람당 한 장의 카드로 관리하는 사내 웹 애플리케이션입니다. 시스템 이름은 "인사카드", 첫 버전은 0.1입니다.

**목적**

- 지원부터 퇴사까지 한 사람의 이력을 체계적으로 분류해 저장한다.
- 채용 과정의 서류 검토를 권한이 부여된 실무자에게만 기간을 정해 공유한다.
- 개인정보 관련 법규에 맞게 보관 기간과 접근 기록을 관리한다.

**사용자**

| 역할 | 대상 | 인원 |
| --- | --- | --- |
| 관리자 | C레벨 임원 | 초기 3명, 추가 가능(인원 제한 없음) |
| 사용자 | 면접관 등 서류 검토 실무자 | 필요 시 초대 |

## 2. 상태 정의와 보관·삭제 정책

인사카드는 5개 상태 중 하나를 가지며, 상태마다 보관 기간과 파기 방식이 다릅니다. 원본의 "2개월 후 일괄 삭제"는 관리자 확인 없는 삭제와 진행 중 채용 삭제 문제가 있어, 사전 알림과 보류 예외를 두는 방식으로 바꿨습니다.

보류는 지원중으로만 돌아가며, 재입사자는 새 카드를 만들지 않고 퇴사 카드를 재직으로 되돌립니다.

| 상태 | 의미 | 보관·파기 규칙 |
| --- | --- | --- |
| 지원중 | 서류 접수부터 면접 진행까지 | 지원일로부터 60일간 상태 변경이 없으면 파기 대상. 파기 7일 전 전체 관리자에게 이메일 알림 |
| 보류 | 채용이 길어지거나 추후 연락 예정 | 자동 파기에서 제외. 보류 지정 시 사유와 재검토일 입력 필수 |
| 불합격 | 채용하지 않기로 확정 | 확정일로부터 90일 보관 후 자동 파기  |
| 재직 | 입사 처리 완료 | 자동 파기 없음 |
| 퇴사 | 퇴사 처리 완료 | 퇴사일로부터 3년 보관 후 파기 대상 알림  |

**상태 전환 규칙**

- 지원중에서 재직으로 바꿀 때는 입사일, 부서, 보직 입력이 필수다.
- 재직에서 퇴사로 바꿀 때는 퇴사일과 퇴사 사유 입력이 필수다.
- 퇴사자가 재입사하면 같은 카드를 다시 재직으로 바꾸고, 이전 재직 기간은 이력으로 남긴다.
- 모든 상태 변경은 이벤트 타임라인에 자동 기록된다(변경자, 일시, 이전·이후 상태).

**삭제 규칙**

- 수동 삭제: 관리자만 가능. 삭제 버튼을 누르면 카드 이름을 직접 입력하는 확인 창을 거친다. 복구 불가.
- 자동 파기: 위 표의 규칙에 따르며, 파기 7일 전 알림 후 실행한다. 알림 이메일에는 대상 카드 목록과 "보류로 전환" 링크를 포함한다.
- 파기 후에는 카드 내용과 첨부파일을 모두 지우고, 파기 로그(카드 ID, 파기 일시, 사유, 실행자)만 남긴다. 로그에 이름 등 개인정보는 남기지 않는다.
- 지원자가 서류 반환이나 삭제를 요청하면 관리자가 즉시 파기할 수 있다(채용절차법 반환 청구 대응).

## 3. 인사카드 데이터 항목

한 사람당 인사카드는 하나이며, 항목은 기본 정보와 상태별 추가 정보로 나뉩니다. AI가 채우지 못한 항목은 빈칸으로 둡니다.

**공통 항목(모든 상태)**

| 구분 | 항목 |
| --- | --- |
| 기본 정보 | 이름, 이메일, 전화번호, 지원 경로, 지원일, 지원 포지션(폴더) |
| 학력 | 학교명(대학 또는 고교), 전공, 성적(평점/만점), 졸업 연월 |
| 기타 이력 | 특별활동, 교육기관(학원·부트캠프) 이수 이력 |
| 경력 | 회사명, 보직, 재직 기간(시작·종료 연월), 주요 업무 — 최신순 정렬 |
| 공백 기간 | 자동 계산 결과(아래 규칙) |
| 개발자 정보 | GitHub 링크, 주요 프로젝트명과 핵심 요약 |
| 첨부파일 | 이력서 원본, 포트폴리오 등 파일 목록 |
| 조회 가능자 | 이 카드를 볼 수 있는 사람의 이름과 권한 만료일 |
| 성별 | 이력서로부터 유추할 수 있는 성별 |

**공백 기간 계산 규칙**

- 학교, 교육기관, 회사, 3개월 이상 아르바이트 중 어디에도 속하지 않은 기간을 공백으로 본다.
- 3개월 이상인 공백만 표시한다 **(기본값)**.
- 기간이 겹치면 합쳐서 계산한다.
- 시작·종료 연월이 불명확한 항목은 "기간 불명확"으로 따로 표시하고 공백 계산에서 제외한다.
- 계산 결과는 참고용이며, 관리자가 수정할 수 있다.

**재직 상태 추가 항목**

- 입사일, 부서, 보직(변경 시 이력으로 남김)
- 연도별 평가: 등급(A·B·C·D)과 코멘트를 함께 입력. 입사 연도부터 현재 연도까지 입력 가능하며, 연도를 코드에 고정하지 않는다.

**퇴사 상태 추가 항목**

- 퇴사일, 퇴사 사유(자발·권고·계약만료·기타), 퇴사 메모

**수집 금지 항목**

AI 추출과 수동 입력 모두에서 아래 항목은 저장하지 않습니다. 이력서에 있어도 무시합니다.

- 사진, 생년월일·나이, 주민등록번호
- 출신 지역, 혼인 여부, 가족 사항(가족의 학력·직업·재산 포함)
- 키·체중 등 신체 조건, 종교, 재산

## 4. 인사카드 생성과 AI 추출

관리자는 폴더를 고르고 파일을 올리면, AI가 항목을 채운 "검토 화면"을 거쳐 저장합니다. AI 결과는 바로 저장하지 않습니다.

**생성 흐름**

1. 관리자가 폴더(지원 포지션)를 선택한다.
2. 이력서와 관련 파일을 끌어다 놓아 업로드한다(여러 개 가능).
3. 시스템이 이메일·전화번호로 기존 카드와 중복 여부를 확인한다. 중복이면 "기존 카드에 추가" 또는 "새 카드 생성"을 묻는다.
4. AI가 항목을 추출해 검토 화면에 채운다. 각 값 옆에 원문 근거 문장을 표시하고, 신뢰도가 낮은 값은 강조한다.
5. 관리자가 확인·수정 후 저장한다. 파일 없이 수동으로만 입력해 저장할 수도 있다.

**지원 파일 형식**

| 형식 | 처리 방식 |
| --- | --- |
| PDF(텍스트) | 텍스트 직접 추출 |
| PDF(스캔)·JPG·PNG | OCR 후 추출 |
| DOCX | 텍스트 직접 추출 |
| HWP·HWPX | 텍스트 변환 후 추출. 변환 실패 시 "수동 입력 필요" 표시 |

- 파일 1개당 최대 20MB, 카드당 최대 10개 **(기본값)**.
- 읽을 수 없는 파일은 첨부만 하고 "추출 실패"로 표시한다. 단 포트폴리오 파일등을 너무 상세히 읽을 필요는 없다. 

**AI 처리 규칙**

- OpenAI API 키는 설정 메뉴에서 입력하며, 모델명도 설정에서 바꿀 수 있게 한다.
- 3장의 수집 금지 항목은 프롬프트 단계에서 추출하지 않도록 지시하고, 응답에 포함되어도 저장 전에 걸러낸다.
- AI 응답은 정해진 JSON 형식으로 받고, 형식이 틀리면 1회 재시도 후 실패 처리한다.
- GitHub는 링크와 공개 저장소의 README·주요 언어만 읽어 요약한다. 비공개 저장소는 링크만 저장한다.
- 호출마다 사용 토큰 수를 기록한다(9장 하단 표시, 설정 메뉴 월별 집계).

## 5. 이벤트 타임라인, 평가, 면접 의견

카드의 모든 기록은 하나의 타임라인에 시간순(최신이 위)으로 보이며, 이벤트 삭제는 "휴지통"으로 이동해 복구할 수 있습니다.

**이벤트**

- 입력 항목: 날짜(연·월·일), 제목, 내용(이슈/메모).
- 타임라인 상단의 한 줄 입력창에서 바로 추가하고, Enter로 즉시 저장한다.
- 수정·삭제는 관리자만 가능하다. 수정 시 이전 내용을 이력으로 남긴다.
- 삭제한 이벤트는 카드별 "삭제된 이벤트"에 남고, 관리자가 복구할 수 있다. 삭제자와 삭제 일시를 표시한다.
- 상태 변경, 권한 부여·만료는 시스템 이벤트로 자동 기록된다(사용자가 삭제 불가).

**연도별 평가(재직자)**

- 등급(A·B·C·D)과 코멘트를 함께 입력해야 저장된다.
- 한 연도에 평가 하나. 수정 시 이력이 남는다.
- 관리자만 입력·조회할 수 있다. 사용자에게는 평가가 보이지 않는다 **(기본값)**.

**면접 의견(지원자)**

원본에는 사용자가 읽기만 가능해 면접관이 의견을 남길 곳이 없었습니다. 이를 보완합니다.

- 읽기 권한이 있는 사용자는 면접 의견을 작성할 수 있다(추천·보류·비추천 + 코멘트).
- 사용자는 자기 의견만 수정할 수 있고, 다른 사용자의 의견은 볼 수 없다 **(기본값)**.
- 관리자는 모든 의견을 본다.

## 6. 목록, 검색, 폴더

인사카드 보기 화면은 왼쪽 폴더 트리와 오른쪽 카드 목록으로 구성됩니다.

**목록**

- 기본 열: 이름, 상태, 폴더, 학교, 최근 회사, 지원일(또는 입사일), 권한 만료일(사용자 화면).
- 모든 열 머리글을 눌러 오름·내림차순 정렬한다.
- 상태별 필터(지원중·보류·불합격·재직·퇴사)를 제공한다.
- 한 페이지 50건, 페이지 이동.

**검색**

- 검색 대상: 이름, 학교명, 회사명, 프로젝트명.
- 입력하는 즉시 결과를 갱신한다. 사용자는 권한 있는 카드 안에서만 검색된다.

**폴더**

- 폴더는 2단계까지 중첩 가능하다(예: 2026 상반기 > 백엔드 개발자) **(기본값)**.
- 카드 하나는 폴더 하나에만 속한다. 다른 폴더로 이동할 수 있다.
- 폴더 생성·이름 변경·삭제는 관리자만 가능하다. 카드가 들어 있는 폴더는 삭제할 수 없다.
- 폴더 없는 카드는 "미분류"에 들어간다.
- 관리자 전용 CSV 내보내기를 제공한다. 내보내기는 감사 로그에 남는다.

## 7. 계정과 권한

새 카드는 관리자만 볼 수 있고, 사용자에게는 카드나 폴더 단위로 4주짜리 읽기 권한을 줍니다. 카드와 폴더 권한이 겹치면 **만료일이 더 늦은 쪽**을 적용합니다.

**역할별 기능**

| 기능 | 관리자 | 사용자 |
| --- | --- | --- |
| 인사카드 생성 | 가능 | 불가(메뉴 숨김) |
| 인사카드 보기 | 전체 | 권한 받은 카드만 |
| 카드 수정·삭제, 이벤트 수정·삭제 | 가능 | 불가 |
| 면접 의견 작성 | 가능 | 권한 받은 지원자 카드에 가능 |
| 첨부파일 다운로드 | 가능 | 불가, 화면 미리보기만 **(기본값)** |
| 연도별 평가 조회 | 가능 | 불가 |
| 설정 메뉴 | 가능 | 불가(메뉴 숨김) |

**읽기 권한 규칙**

- 관리자가 카드 또는 폴더에 사용자를 지정해 읽기 권한을 준다. 기본 기간은 부여일로부터 4주다.
- 폴더 권한은 부여 이후 그 폴더에 새로 추가된 카드에도 적용된다.
- 만료일은 카드 상세와 사용자 목록 화면에 표시된다.
- 관리자는 "4주 연장" 버튼으로 만료일을 현재 만료일 기준 4주 늘리거나, 즉시 회수할 수 있다.
- 만료 3일 전 사용자와 관리자에게 이메일 알림을 보낸다.
- 카드가 불합격·퇴사 상태가 되면 사용자 권한은 즉시 회수된다.

**계정 관리**

- 최초 관리자: 설치 시 명령어(`create_admin`)로 생성한다.
- 사용자 추가: 관리자가 이름과 이메일을 입력하면 초대 이메일이 발송되고, 사용자가 링크에서 비밀번호를 설정한다. 초대 링크 유효기간 72시간.
- 관리자 추가는 관리자만 가능하며, 추가 즉시 전체 관리자에게 알림 이메일을 보낸다.
- 관리자 강등·삭제도 전체 관리자에게 알린다. **마지막 관리자는 삭제·강등할 수 없다.**
- 사용자 비활성화: 퇴사한 실무자 등은 비활성화하며, 모든 권한이 회수된다. 기록 보존을 위해 계정은 삭제하지 않는다.
- 설정 > 사용자 화면: 전체 사용자 목록, 비밀번호 재설정 링크 발송, 사용자별 보유 권한과 만료일, 사용자별 조회 이력을 보여준다.

## 8. 보안과 개인정보

인사 데이터는 유출 시 피해가 크므로, 관리자를 포함한 모든 접근을 기록하고 관리자 계정에는 2단계 인증을 적용합니다.

**인증**

- 비밀번호: 10자 이상, 영문·숫자·특수문자 중 3종 이상. bcrypt 또는 argon2로 해시 저장.
- 로그인 5회 연속 실패 시 15분 잠금.
- 관리자 계정은 2단계 인증(OTP 앱) 필수, 사용자는 선택.
- 30분 동안 활동이 없으면 자동 로그아웃.

**접근 기록(감사 로그)**

- 모든 계정(관리자 포함)의 카드 조회, 수정, 삭제, 파일 열람·다운로드, 권한 변경, CSV 내보내기를 기록한다.
- 기록 항목: 사용자, 일시, 대상 카드, 행위, 접속 IP.
- 감사 로그는 관리자만 조회할 수 있고, 누구도 수정·삭제할 수 없다. 1년 보관 **(기본값)**.

**데이터 보호**

- SSL(HTTPS) 필수. HTTP 접속은 HTTPS로 리다이렉트한다.
- SQL 인젝션, XSS, CSRF 방어. ORM 사용, 입력값 검증, 출력 이스케이프, CSRF 토큰.
- 업로드 파일은 웹 루트 밖에 저장하고, 파일명은 무작위로 바꾸며, 서버에서 권한 확인 후에만 내려준다.
- 업로드 파일과 전화번호·이메일 필드는 암호화해 저장한다.
- 카드 화면과 미리보기에 조회자 이름과 조회 시각을 옅은 워터마크로 표시한다.
- 접속 허용 IP 목록 설정 기능(사내 IP만 허용, 기본값은 꺼짐).
- 매일 DB와 업로드 파일을 자동 백업하고 7일치를 보관한다 **(기본값)**.

**개인정보 관련**

- OpenAI API는 데이터 학습에 사용되지 않는 조건인지 확인하고, 설정 화면에 그 사실과 확인 날짜를 표시한다.
- 로그인 화면 경고문(설정에서 수정 가능): "본 사이트의 모든 정보는 개인정보를 포함한 회사 비밀 정보입니다. 권한이 없는 사람의 접속을 금지합니다. 화면 내용을 촬영·복사·외부 공유하지 마십시오."

## 9. 화면 구성

화면은 흑백 텍스트 위주로 단순하게 만들고, 왼쪽에 대분류 메뉴 세 개만 둡니다. 단 미적인 그레이/흑백 톤의 아이콘을 적절하게 추가한다.

| 메뉴 | 하위 화면 | 접근 |
| --- | --- | --- |
| 인사카드 생성 | 파일 업로드 → AI 검토 화면 → 저장 | 관리자 |
| 인사카드 보기 | 폴더 트리 + 목록, 카드 상세(정보·타임라인·면접 의견·첨부·권한) | 관리자, 사용자 |
| 설정 | 사용자 관리, 권한 현황, 감사 로그, 휴지통(삭제 이벤트), 파기 예정 목록, OpenAI 설정, 이메일(SMTP) 설정, 보관 기간·경고문 설정, 토큰 사용량 | 관리자 |

**공통 규칙**

- 흑백 아이콘만 사용하고, 꾸밈 요소는 넣지 않는다.
- 화면 상단 왼쪽에 "인사카드 v0.1" 표시.
- 화면 하단에 보안 주의 문구와 이번 달 토큰 사용량 표시(사용자 화면에는 보안 주의 문구만).
- PC 웹 전용. 화면 폭 1024px 미만이거나 모바일 기기로 접속하면 "모바일은 지원하지 않습니다. PC에서 접속해 주세요." 안내만 표시한다.
- 입력 후 저장은 페이지 새로고침 없이 즉시 반영한다.

## 10. 기술 사항과 설치

백엔드는 Python FastAPI, 프론트엔드는 React, DB는 PostgreSQL로 하고, docker compose 한 번으로 Ubuntu 최신 LTS에서 실행되게 합니다.

| 구분 | 사용 기술 |
| --- | --- |
| 프론트엔드 | React + TypeScript (Vite) |
| 백엔드 | Python 3.12, FastAPI, SQLAlchemy, Alembic(DB 마이그레이션) **(기본값)** |
| DB | PostgreSQL 16 |
| 예약 작업 | 자동 파기, 만료 알림, 백업 — 매일 새벽 실행 |
| 웹 서버 | Nginx(HTTPS, 리버스 프록시) |
| 인증서 | 도메인이 있으면 Let's Encrypt 자동 발급, 사내망 전용이면 자체 서명 인증서 |
| 문서 처리 | PDF·DOCX 추출 라이브러리, OCR(Tesseract 한국어), HWP 변환 도구 |
| 실행 | docker compose |

**모듈 분리**

- `card` 앱: 인사카드, 폴더, 이벤트, 평가, 면접 의견, 파일, AI 추출.
- `admin` 앱(설정): 사용자, 권한, 감사 로그, 보관 정책, 시스템 설정.
- 공통 모듈: 인증, 이메일 발송, 암호화.

**설정 화면에서 입력하는 값**

- OpenAI API 키, 사용 모델명
- SMTP 서버 주소, 포트, 계정, 발신 주소(초대·재설정·알림 메일용)
- 보관 기간(지원중 60일, 불합격 90일 등 2장 값), 권한 기본 기간(4주)
- 로그인 경고문, 하단 보안 문구, 허용 IP 목록

**install.txt에 포함할 내용**

1. Ubuntu에 Docker와 docker compose 설치 명령
2. 소스 내려받기와 `.env` 파일 작성(DB 비밀번호, 암호화 키, 도메인)
3. `docker compose up -d` 실행
4. 최초 관리자 생성 명령
5. HTTPS 인증서 설정(도메인/사내망 두 경우)
6. 백업 위치 확인과 복원 방법
7. 버전 업데이트 방법
